# Nucleus 4.1.0 — release notes (candidate)

Consolidated refresh: same behaviour, a fraction of the weight, and the Linux
path actually works.

## Size

| | Before | After |
|---|---|---|
| Repository | 133 MB | 91 MB |
| `assets/` | 72 MB | 21 MB |
| Page CSS | 547 KB | **115 KB** (22 KB gzip) |
| Page JS | 1,172 KB | **199 KB** (65 KB gzip) |

Budgets: CSS ≤ 120 KB, JS ≤ 200 KB — both met.

## UI

- WowDash theme removed: `style.css` (297 KB), the demo image kits (36 MB) and
  930 KB of unloaded demo chart scripts are gone.
- Nucleus now renders on **2ti-theme** (`assets/2ti/tokens.css`, `theme.css`,
  `nucleus.css`), the house design system, with light and dark from tokens.
- Bootstrap is served as a **tree-shaken subset** (227 KB → 86 KB) generated by
  `tools/purge-bootstrap.py`; state classes Bootstrap's JS toggles are kept.
- Icons are **Iconify only** — Remixicon and Font Awesome (10 MB of fonts,
  138 KB CSS) removed; the views already used 521 `<iconify-icon>` elements.
- Uppercase group labels are gated to `[dir="ltr"]` so Arabic keeps its joining.

## Platform interface

- `platform.php` is the single file that differs between products:
  `product`, `platform`, `update_repo`.
- `includes/UpdateManager.php` is byte-identical across Nucleus and
  Laragon-Dashboard: it reads identity from `platform.php`, fails closed when it
  is absent, and rejects an update package that declares another product.

## Fixes

- **Services** — `restart` was `stop()` + 0.5 s + `start()`, and `stop()`
  reported failure while the unit was still `deactivating`. Now one
  `systemctl restart`, state polling, and an exit-status check. Actions run
  through `/usr/local/bin/nucleus-service`, which whitelists four actions and
  nine units.
- **Projects** — `create`, `delete` and `library download` called
  `validate_csrf_token()`, which does not exist, so every request fataled with
  HTTP 500. Fixed to `verifyCSRFToken()`.
- **Project root** — `getWwwPath()` returned the dashboard's own directory when
  served from its own vhost; it now honours `document_root` from
  `data/preferences.json`.
- **Symlinked web root** — `create_project` compared a raw path to
  `realpath(documentRoot)`, so creates failed whenever the web root was a
  symlink. Resolved before the guard.
- **Preferences** — a GET ran the save path with no CSRF. Now POST-only with
  token, and an empty payload is rejected.
- **API status codes** — validation errors answered 400 instead of 500.

## Host requirements (Linux)

See `docs/host-setup.md`: setgid group-writable web root, Apache `UMask=0002`,
the `*.local` wildcard vhost pair, and the service helper.

## Verified

- 16 routes return 200; zero missing asset references.
- Class-coverage gate over 440 rendered classes: 0 regressions.
- Create → delete project cycle through the real vhost.
- Restart / stop / start of a service through the API, with an honest failure
  for a unit that does not exist.

## Known limits

- Apache runs PHP as `www-data`; file management requires the web root to be
  group-writable (documented), or a PHP-FPM pool running as the owner.
- `api/logs.php`, `api/tools.php`, `api/plugins.php` actions were not exercised
  beyond their validation paths.
